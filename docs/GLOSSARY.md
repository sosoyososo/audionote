# GLOSSARY

> Agent-readable term → symbol map. **Use `codegraph_explore <term>` first**; this file is for terms that don't have an obvious code symbol, or when you need to verify which exact name owns a concept.

> Format: `Term — file:line — short note`. If you can't find a term here, search code before assuming it doesn't exist.

## Domain: Recording / Recognition

| Term | Symbol | Note |
|---|---|---|
| **assess-and-enhance pipeline** | `TranscriptionViewModel.assessAndEnhance` at `ios/AudioNote/ViewModels/TranscriptionViewModel.swift:261` | Phase-2 dispatch with four arms: `.online` → LLM, `.onDevice` → LLM-or-enhance, `.failed` → retry-from-file, `.pending` → retry-from-file (never the LLM). Locked by ADR-0001 §30 and ADR-0005 |
| **RecordingViewModel** | _(does not exist)_ | **Misnomer trap.** The orchestrator is `TranscriptionViewModel` (line 1 of its file). Don't create one — this name will confuse future readers |
| **RecognitionMode** | top-level `enum RecognitionMode` (file scope, **not** nested in `TranscriptionRecord`) at `ios/AudioNote/Models/TranscriptionRecord.swift:3` | Enum: `.online` / `.onDevice` / `.enhanced` / `.failed` / `.pending`. **Never** add a 6th case without extending `assessAndEnhance` (ADR-0001 §30) and deciding which recovery queue admits it (ADR-0005) |
| **enhanced** | `RecognitionMode.enhanced` | Set when `SpeechRecognizer.recognizeFromFile` succeeds; means we re-ran recognition against the saved audio, not the live stream |
| **pending** | `RecognitionMode.pending` at `ios/AudioNote/Models/TranscriptionRecord.swift:19` | Audio exists, transcript does not — the recognizer errored and returned nothing. Distinct from `.failed` (a retry already happened and also came back empty). Must never reach the LLM: its `content` is empty, and an empty prompt comes back hallucinated. See ADR-0005 |
| **PendingRecognitionPolicy** | `ios/AudioNote/Services/PendingRecognitionPolicy.swift:21` (`enum`, pure statics only) | Every decision that stands between a recording and its transcript, extracted as pure statics because `TranscriptionViewModel`'s collaborators are `private let` singletons and so the VM itself cannot be unit-tested. Members: `classify`, `llmQueue`, `recognitionRetryQueue`, `isHandEdited`, `llmInputText`, `handEditMarker`, `isLLMEligible`, `shouldRefuseToRecord`. See ADR-0005 |
| **assess** | informal — no symbol | The dispatch decision itself, lived in `assessAndEnhance`. Don't rename files to "Assessment" |
| **mergeTag(_:from:)** | `ios/AudioNote/ViewModels/TranscriptionViewModel.swift` | Folds tags into one via `TagMerger` + `TranscriptionStorage.mergeTags`, then reloads. **The `selectedTags` remap is load-bearing and looks deletable — it is not.** Filter by `工作项`, merge `工作项` into `工作`, and without the remap `selectedTags` still names a tag no record carries: `displayedRecords` matches nothing and the library renders **empty, with no error**, because the filter is working exactly as written against a name that no longer exists. The invariant to assert is a **superset**, not an unchanged count — after the merge the target's own records legitimately belong to the same filter, so a *larger* list is correct and hiding it would be the bug. Bails early (no write, no reload) when no record actually carries a source tag, so a no-op merge doesn't rewrite the file |

## Domain: Persistence

| Term | Symbol | Note |
|---|---|---|
| **TranscriptionRecord** | `ios/AudioNote/Models/TranscriptionRecord.swift:37` | The on-disk model. JSON-serialized by `TranscriptionStorage`. Adding a field is a **schema change** — see Contracts (not yet written) |
| **optimizedContent** | field on `TranscriptionRecord` (`ios/AudioNote/Models/TranscriptionRecord.swift:50`) | **Overloaded — read this before trusting the old description.** It holds the text content was *derived from*, and it is set by two different writers that the record cannot tell apart: the LLM path (`processWithLLM` writes the pre-LLM original) and the hand-edit path (`PendingRecognitionPolicy.handEditMarker` writes the pre-edit text). **Invariant**: when `optimizedContent != content`, auto-enhance and every automatic recovery pass MUST skip. The predicate for it is `PendingRecognitionPolicy.isHandEdited(_:)`, which therefore means "content has diverged from its source", **not** "a human typed this" — essentially every LLM-processed record satisfies it. A hand-edited record may carry **any** `llmProcessingStatus`, including `.failed`: `updateRecord` derives the marker independently of status, so status is not evidence of who wrote the text. Consequences: the 优化后 badge must stay gated on `llmProcessingStatus == .completed` and never on this predicate, and LLM input must resolve through `PendingRecognitionPolicy.llmInputText(for:)` rather than a bare `optimizedContent ?? content`. See ADR-0005 |
| **audioFileName** | field on `TranscriptionRecord` | UUID + `.m4a`. File URL is reconstructed via `AudioRecorderService.generateFileUrl(for: uuid)` — **do not** store URLs directly |
| **archived** | field on `TranscriptionRecord` (Bool, default `false`) | Splits the library in two. `LibraryListView` shows one half at a time, chosen by `TranscriptionViewModel.isArchiveMode` — archive mode is a *view mode*, not a filter, so search and tag chips apply identically to both halves and `archivedRecordCount` ignores them entirely |
| **archivedAt** | field on `TranscriptionRecord` (`Date?`, default `nil`) | Set when archived; cleared on unarchive. Drives archive ordering and freshness logic if added later |
| **TaggedItem** | `ios/AudioNote/Models/TranscriptionRecord.swift:32` | One LLM tag: `name` + `score` in `[0.0, 1.0]`. Compare names only through `TagIdentity`. **`name` is normalized (`TagIdentity.normalized`) on both `init` and `decode`** — this type is the only way a tag enters the app (LLM results and on-disk records both decode through it), so trimming there heals legacy padded tags on load with **no migration**. The legacy `[String]` JSON shape goes through a separate branch (`decodeTags`) and lands in the same `init`, so it is trimmed too |
| **TagIdentity** | `ios/AudioNote/Utilities/TagIdentity.swift:15` (`enum`; static, namespace only) | **The one definition of "the same tag".** Two normalization axes, deliberately separate. **Case** folds in `key(_:)` (comparison) but **not** in `normalized(_:)` (display form): tags come from an LLM that picks casing per record, so `Work` and `work` otherwise become two chips that each filter only to their own spelling — the tag shows in the row and matches nothing in the list. Identity is therefore case-insensitive, while the *displayed spelling* stays a separate, visible decision made by `availableTags` (most frequent, tie → highest score, then raw `<` for determinism). **Whitespace** folds in **both**, because leading/trailing spaces are never intentional and are invisible on screen. Every tag comparison goes through it — library filter + rank sort (`displayedRecords`), chip grouping (`availableTags`), `tagCount(for:)`, `toggleTag`, the detail-page highlight (`TagFlowView`), and related-notes shared tags in **both** `RelatedNotesService.prescreen` and `RelatedNotesSectionBuilder.rows` (they must agree, or a row renders chips for a link earned on different grounds). CJK has no case, so the case axis is a no-op for Chinese tags — for a Chinese library the real dirty-data source is **vocabulary** drift (`工作` / `工作项` / `工作会议`), which chip merging provably cannot fix because those are genuinely different strings; that is what the prompt's vocabulary hint addresses. A whitespace-only tag normalizes to `""` and is skipped in `availableTags` and `prescreen` (an empty chip is an untappable pill; a blank "shared tag" would inflate the related-notes score directly) |
| **TranscriptionStorage** | `ios/AudioNote/Services/TranscriptionStorage.swift:26` | Single source of truth for read/write of records. Always go through this; don't write JSON manually |
| **mergeTags(into:from:)** | `ios/AudioNote/Services/TranscriptionStorage.swift` | Rewrites the whole library through **one** `saveAll`, deliberately *not* a loop over `save(_:)`: `save` re-reads and re-encodes the entire file per call, so a merge touching 400 records would be 400 full read-modify-write cycles, and a failure halfway through would leave a half-merged library that still parses and still looks intact. `.atomic` means the rewrite lands whole or not at all. Whole library including archived records |
| **StorageCoordinator** | `ios/AudioNote/Services/StorageCoordinator.swift` (singleton, `@MainActor`) | Owns the user-picked `AudioNote` folder URL in the Files app + its security-scoped bookmark (one, root-level, persisted in `UserDefaults`). **All** file path resolution goes through `StorageCoordinator.shared.audioURL(for:)` / `.jsonURL` / `.rootURL`. Never write to `Documents/` directly — old sandbox data is unrecoverable. Bootstrap on launch (`ContentView.onAppear`); gate the tab UI on `.isReady`; release/re-acquire on scene-phase transitions (wired in `AudioNoteApp` `WindowGroup`) |

## Domain: Services (boundary, do not cross directly)

| Term | Symbol | Note |
|---|---|---|
| **AudioRecorderService** | `ios/AudioNote/Services/AudioRecorderService.swift:4` | Owns audio file naming and lifecycle. Use `generateFileUrl(for:)` to derive URLs |
| **SpeechRecognizer** | `ios/AudioNote/Services/SpeechRecognizer.swift:44` | Wraps Apple `SFSpeechRecognizer`. Two modes: live stream (`startRecording`) and file re-recognition (`recognizeFromFile`) |
| **LLMService** | `ios/AudioNote/Services/LLMService.swift` | Two entry points: `optimizeAndProcess(text, profile:, apiKey:, existingTags:)` (the merged variant — see ADR-0002 / 0003) and `ping(profile:, apiKey:)` (lightweight reachability check for Settings). **Caller must supply the active profile + API key** — there is no global default. `existingTags` is the library's tag vocabulary (defaulted to `[]`, so a cold library is unchanged); it is an *input*, never a prompt override. The prompt text itself stays internal and is built by `optimizeAndProcessPrompt(existingTagVocabulary:)` — internal rather than private so a test can pin it, the same reason `findRelatedPrompt` is |
| **maxTagVocabulary** | `LLMService.maxTagVocabulary` = 30 | Cap on how many existing tag names are injected into the prompt. The library's most-used tags win; beyond the cap a rarer tag is simply not mentioned, which costs a new near-synonym at worst but bounds the prompt |
| **existingTagVocabulary** | `TranscriptionViewModel.existingTagVocabulary` | The tag names already in the library, most-used first, trimmed, blanks skipped, capped at `LLMService.maxTagVocabulary`. Fed to `optimizeAndProcess` so the model is told which spellings exist instead of inventing `工作` / `工作项` / `工作会议` per record — **the one dirty-data source chip merging cannot fix**, since those are genuinely different strings. Whole library, not the live half: the archive is storage, not a separate vocabulary. Casing is deliberately **not** unified here — folding it would show the model a tidy list while hiding the very drift it is being asked to notice |
| **NetworkMonitor** | `ios/AudioNote/Utilities/NetworkMonitor.swift:4` | Singleton `.shared`. `checkConnectivity()` is the gate before any LLM/online call |
| **AIProcessingService** | `ios/AudioNote/Services/AIProcessingService.swift:3` | Background queue / retry helper. `processPendingRecords` runs on app launch for records left in intermediate states |
| **NoteRelation** | `ios/AudioNote/Models/NoteRelation.swift:8` | One undirected "these two notes are related" edge, stored in `relatedNotes.json`. The `init(a:b:score:)` normalizes so `a.uuidString <= b.uuidString`, which makes the pair's identity order-independent — `key` is `min(a,b)|max(a,b)`, the identity `upsert` dedupes on. Note the synthesized `init(from:)` bypasses that normalization, so a hand-edited file can hold a non-normalized edge. `otherID(from:)` resolves the counterpart; the storage layer does **not** guard self-edges |
| **RelatedNote** | `ios/AudioNote/Models/NoteRelation.swift:45` | An edge resolved from one note's point of view — the *other* note's `id` plus the pair's `score`. Produced only by `RelatedNotesStorage.related(to:)`, so no consumer deals with which side of the edge it holds |
| **RelatedNotesStorage** | `ios/AudioNote/Services/RelatedNotesStorage.swift:11` (`final class`, singleton `.shared`; `init(fileURL:)` is the test seam) | Reads/writes `relatedNotes.json` via `StorageCoordinator.relatedNotesURL`, a sibling of `transcriptions.json`. Deliberately does not cache. `related(to:)` is `async`, **never throws**, and returns `[]` on a read error (spec §6's read/render policy); it filters by `minimumScore` (0.3) and sorts by score desc with a `.uuidString` tie-break, so the list cannot reshuffle between launches. `upsert(_:)` / `removeAll(involving:)` / `loadAll()` **do** throw on a read failure rather than defaulting to an empty merge set — overwriting an undecodable file would destroy relations that are never recomputed. The swallow belongs at the caller (`link`/`unlink`), not here. Archive deliberately does not call `removeAll` |
| **RelatedNotesService** | `ios/AudioNote/Services/RelatedNotesService.swift:69` (`struct`; one instance per view model) | Owns prescreen → LLM → sanitize → persist. `link(for:)` and `unlink(recordId:)` both **never throw**. Constants: `maxCandidates` 20, `minimumCandidates` 3 (below this, bail before spending a call), `maxRelated` 5. Both methods run inside the same `Gate.withLock`, which serializes the read-modify-write on `relatedNotes.json` — a delete racing a link would otherwise lose an edge permanently. `link(for:)` is **idempotent with respect to existing edges**: it excludes already-linked notes from the *candidate list* (not just the result), so a re-analysis can create new edges but never re-rate or destroy one — §4.4 measures a pair exactly once, and `upsert` would otherwise replace the score on a row another note's page is already showing. **Caller's contract:** the note must already be persisted *and* its optimized text on screen before `link` is awaited, or the second round trip (1–3s) masks the first call's output |
| **Gate** | `ios/AudioNote/Services/RelatedNotesService.swift:34` (`actor`, one per `RelatedNotesService` instance) | Async FIFO mutex over the relation file. A second caller **queues** — it does not skip, coalesce, or bail. `withLock(_:)` exists because `await` is illegal in `defer`, so an `acquire()`/deferred-`release()` pair would release onto an unscheduled `Task` |
| **TagMerger** | `ios/AudioNote/Services/TagMerger.swift` (`enum`; pure statics, no I/O) | Rewrites tags so N source tags collapse into one target. Pure by construction — same precedent as `PendingRecognitionPolicy` — because `TranscriptionViewModel.storage` is a private singleton with no injection seam, so the rewrite has to be separable from the write to be testable at all. **The target's own identity is part of the hit set, not a side effect of the union**: a record already tagged `工作` (0.4) that also carries `工作项` (0.9) must become ONE `工作` at 0.9 — leave the target out of the set and its existing entry survives while a second `工作` is inserted beside it. Surviving score is `max` of the collapsed entries, not first and not average. Replaces the hits in place at the first hit's position, so tag order stays score-ordered. `remappedSelection(_:into:from:)` is the second half: see `mergeTag` |
