| **PendingRecognitionPolicy** | `ios/AudioNote/Services/PendingRecognitionPolicy.swift:21` (`enum`, pure statics only) | Every decision that stands between a recording and its transcript, extracted as pure statics because `TranscriptionViewModel`'s collaborators are `private let` singletons and so the VM itself cannot be unit-tested. | **assess** | informal — no symbol | The dispatch decision itself, lived in `assessAndEnhance`. Don't rename files to "Assessment" |
| **recoveryCandidates(from:llmLimit:)** | `ios/AudioNote/Services/PendingRecognitionPolicy.swift` (pure static) | The one place that decides what a recovery sweep acts on: `RecoveryCandidates` splits the library into `neverProcessed` / `unfinishedLLM` / `recognitionRetry`. **Both sweeps call it** — the launch sweep and the network-recovery sweep — so the two cannot drift; two sweeps with their own candidate functions would drift invisibly, with the network sweep still looking right while the launch sweep quietly skipped something. The LLM pool is `llmQueue` records whose status is `nil` / `.failed` / `.processing`; `.pending` is excluded by `llmQueue` itself (ADR-0005). `.processing` is included because it is a **terminal** status — the app was killed mid-call, and nothing else in the app would ever move it. See ADR-0006 |
| **launchLLMLimit** | `ios/AudioNote/Services/PendingRecognitionPolicy.swift` | **10 records per launch**, counting the "never processed" and "unfinished" buckets together — a budget for the sweep, not per bucket. The launch sweep is unattended, so its cost has to be bounded; the network-recovery sweep is **not** capped (the user is waiting for it, and capping it would mean toggling the network once per batch). The cap sorts **oldest first** — the records that have been waiting longest go first, and the ones it skips are the most recent. It does **not** bound `recognitionRetry`: re-recognition is Apple's speech service, not a paid API, and ADR-0005 §4.6 requires retries to be unlimited. See ADR-0006 |
| **isAwaitingUserLLMResult** | `ios/AudioNote/ViewModels/TranscriptionViewModel.swift` | `isLLMProcessing && !isBackgroundRecovery`. The views read this instead of `isLLMProcessing`, because those flags are **global, not per record**: a background sweep processing record #37 would otherwise replace the recording screen's transcript area with a spinner about somebody else's record, and replace the detail view's LLM button with a disabled one. The app would be reporting its own housekeeping as the user's request. `hasUserFacingLLMFailure` is the same idea for the failure flag (which is sticky, so a sweep's failure surfaces once the sweep ends — delayed, not swallowed). See ADR-0006 |
| **mergeTag(_:from:)** | `ios/AudioNote/ViewModels/TranscriptionViewModel.swift` | Folds tags into one via `TagMerger` + `TranscriptionStorage.mergeTags`, then reloads. **The `selectedTags` remap is load-bearing and looks deletable — it is not.** Filter by `工作项`, merge `工作项` into `工作`, and without the remap `selectedTags` still names a tag no record carries: `displayedRecords` matches nothing and the library renders **empty, with no error**, because the filter is working exactly as written against a name that no longer exists. The invariant to assert is a **superset**, not an unchanged count — after the merge the target's own records legitimately belong to the same filter, so a *larger* list is correct and hiding it would be the bug. Bails early (no write, no reload) when no record actually carries a source tag, so a no-op merge doesn't rewrite the file |

## Domain: Persistence

| Term | Symbol | Note |
|---|---|---|
| **TranscriptionRecord** | `ios/AudioNote/Models/TranscriptionRecord.swift:63` | The on-disk model. JSON-serialized by `TranscriptionStorage`. Adding a field is a **schema change** — see Contracts (not yet written) |
| **optimizedContent** | field on `TranscriptionRecord` (`ios/AudioNote/Models/TranscriptionRecord.swift:76`) | **Overloaded — read this before trusting the old description.** It holds the text content was *derived from*, and it is set by two different writers that the record cannot tell apart: the LLM path (`processWithLLM` writes the pre-LLM original) and the hand-edit path (`PendingRecognitionPolicy.handEditMarker` writes the pre-edit text). **Invariant**: when `optimizedContent != content`, auto-enhance and every automatic recovery pass MUST skip. The predicate for it is `PendingRecognitionPolicy.isHandEdited(_:)`, which therefore means "content has diverged from its source", **not** "a human typed this" — essentially every LLM-processed record satisfies it. A hand-edited record may carry **any** `llmProcessingStatus`, including `.failed`: `updateRecord` derives the marker independently of status, so status is not evidence of who wrote the text. Consequences: the 优化后 badge must stay gated on `llmProcessingStatus == .completed` and never on this predicate, and LLM input must resolve through `PendingRecognitionPolicy.llmInputText(for:)` rather than a bare `optimizedContent ?? content`. See ADR-0005 |
| **audioFileName** | field on `TranscriptionRecord` | UUID + `.m4a`. File URL is reconstructed via `AudioRecorderService.generateFileUrl(for: uuid)` — **do not** store URLs directly |
| **archived** | field on `TranscriptionRecord` (Bool, default `false`) | Splits the library in two. `LibraryListView` shows one half at a time, chosen by `TranscriptionViewModel.isArchiveMode` — archive mode is a *view mode*, not a filter, so search and tag chips apply identically to both halves and `archivedRecordCount` ignores them entirely |
| **archivedAt** | field on `TranscriptionRecord` (`Date?`, default `nil`) | Set when archived; cleared on unarchive. Drives archive ordering and freshness logic if added later |
| **TaggedItem** | `ios/AudioNote/Models/TranscriptionRecord.swift:41` | One LLM tag: `name` + `score` in `[0.0, 1.0]`. Compare names only through `TagIdentity`. **`name` is normalized (`TagIdentity.normalized`) on both `init` and `decode`** — this type is the only way a tag enters the app (LLM results and on-disk records both decode through it), so trimming there heals legacy padded tags on load with **no migration**. The legacy `[String]` JSON shape goes through a separate branch (`decodeTags`) and lands in the same `init`, so it is trimmed too |
| **TagIdentity** | `ios/AudioNote/Utilities/TagIdentity.swift:23` (`enum`; static, namespace only) | **The one definition of "the same tag".** Two normalization axes, deliberately separate. **Case** folds in `key(_:)` (comparison) but **not** in `normalized(_:)` (display form): tags come from an LLM that picks casing per record, so `Work` and `work` otherwise become two chips that each filter only to their own spelling — the tag shows in the row and matches nothing in the list. Identity is therefore case-insensitive, while the *displayed spelling* stays a separate, visible decision made by `availableTags` (most frequent, tie → highest score, then raw `<` for determinism). **Whitespace** folds in **both**, because leading/trailing spaces are never intentional and are invisible on screen. Every tag comparison goes through it — library filter + rank sort (`displayedRecords`), chip grouping (`availableTags`), `tagCount(for:)`, `toggleTag`, the detail-page highlight (`TagFlowView`), and related-notes shared tags in **both** `RelatedNotesService.prescreen` and `RelatedNotesSectionBuilder.rows` (they must agree, or a row renders chips for a link earned on different grounds). CJK has no case, so the case axis is a no-op for Chinese tags — for a Chinese library the real dirty-data source is **vocabulary** drift (`工作` / `工作项` / `工作会议`), which chip merging provably cannot fix because those are genuinely different strings; that is what the prompt's vocabulary hint addresses — and what that hint does not yet fix is the other half: the vocabulary is capped at the 30 most *frequent* tags (`LLMService.maxTagVocabulary`), while the bloat lives in the long tail, so the model never sees the tags that most need normalizing. See `docs/superpowers/specs/2026-10-26-tag-vocabulary-maintenance-design.md`. A whitespace-only tag normalizes to `""` and is skipped in `availableTags` and `prescreen` (an empty chip is an untappable pill; a blank "shared tag" would inflate the related-notes score directly) |
| **TranscriptionStorage** | `ios/AudioNote/Services/TranscriptionStorage.swift:26` (actor, singleton `.shared`; `init(fileURL:)` is the test seam) | Single source of truth for read/write of records. Always go through this; don't write JSON manually. **`loadOutcome()` is the read that keeps "empty" and "broken" apart** — `.noFile` / `.noFileButAudioRemains(count)` / `.records` / `.corrupted`; `loadAll()` collapses the first two and throws on the last, which is the contract every writer relies on. `save(_:)` propagates a read failure instead of defaulting to an empty library: the old `(try? …) ?? []` turned one corrupt file into total data loss (the next write replaced the whole library with the single record being saved). See ADR-0007 |
| **update-path merge** | `ios/AudioNote/Services/PendingRecognitionPolicy.swift:313` (`mergedRecord(incoming:existing:)`) | The record `TranscriptionViewModel.updateRecord` writes, derived as a pure static so it is testable — the VM reaches `TranscriptionStorage` through a private singleton and cannot be built in a unit test. **Every optional field is `incoming ?? existing`**: a caller that states a value wins, a caller that omits one is *not* asking for it to be cleared. This is what stops `RecordingView.saveEditedText` — which builds a record out of the text alone — from deleting the note's `title` / `summary` / `tags` / `llmProcessingStatus`. The loss is unrecoverable rather than cosmetic: `handEditMarker` marks the record hand-edited, so `llmQueue` excludes it permanently and no sweep puts the metadata back. `archived` is the one exception to the `??` shape (a `Bool` cannot be "unstated"): it is `incoming.archived \|\| existing.archived`, and un-archiving is `unarchiveRecord`, which writes straight to storage. See ADR-0005 |
| **mergeTags(into:from:)** | `ios/AudioNote/Services/TranscriptionStorage.swift` | Rewrites the whole library through **one** `saveAll`, deliberately *not* a loop over `save(_:)`: `save` re-reads and re-encodes the entire file per call, so a merge touching 400 records would be 400 full read-modify-write cycles, and a failure halfway through would leave a half-merged library that still parses and still looks intact. `.atomic` means the rewrite lands whole or not at all. Whole library including archived records |
| **StorageCoordinator** | `ios/AudioNote/Services/StorageCoordinator.swift` (singleton, `@MainActor`) | Owns the user-picked `AudioNote` folder URL in the Files app + its security-scoped bookmark (one, root-level, persisted in `UserDefaults`). **All** file path resolution goes through `StorageCoordinator.shared.audioURL(for:)` / `.jsonURL` / `.rootURL`. Never write to `Documents/` directly — old sandbox data is unrecoverable. Bootstrap on launch (`ContentView.onAppear`); gate the tab UI on `.isReady`; release/re-acquire on scene-phase transitions (wired in `AudioNoteApp` `WindowGroup`). **`.state` (`StorageState`: `.unconfigured` / `.unreachable(reason)` / `.ready`) is the authoritative access state; `.isReady` is a computed `state == .ready`.** The bookmark is **never deleted because a resolution attempt failed** — a broken bookmark does not prove the folder is gone, and destroying the only credential is what turned a recoverable "can't find the folder" into "re-pick from scratch" (and people re-pick into a *new empty folder*, then conclude their data is gone). See ADR-0007 |

| **RelatedNotesService** | `ios/AudioNote/Services/RelatedNotesService.swift:69` (`struct`; one instance per view model) | Owns prescreen → LLM → sanitize → persist. `link(for:)` and `unlink(recordId:)` both **never throw**. Both methods run inside the same `Gate.withLock`, which serializes the read-modify-write on `relatedNotes.json` — a delete racing a link would otherwise lose an edge permanently. `link(for:)` is **idempotent with respect to existing edges**: it excludes already-linked notes from the *candidate list* (not just the result), so a re-analysis can create new edges but never re-rate or destroy one — §4.4 measures a pair exactly once, and `upsert` would otherwise replace the score on a row another note's page is already showing. **Caller's contract:** the note must already be persisted *and* its optimized text on screen before `link` is awaited, or the second round trip (1–3s) masks the first call's output |

| **TagMerger** | `ios/AudioNote/Services/TagMerger.swift` (`enum`; pure statics, no I/O) | Rewrites tags so N source tags collapse into one target. Replaces the hits in place at the first hit's position, so tag order stays score-ordered. `remappedSelection(_:into:from:)` is the second half: see `mergeTag` |

| **FlowPacking** | `ios/AudioNote/Utilities/FlowLayout.swift` (`enum`, pure statics) | The line-breaking algorithm behind `FlowRow`, split out because a `Layout` conformance cannot be unit-tested without rendering a view and this project has no ViewInspector — same reason `PendingRecognitionPolicy` and `TagMerger` are pure. Greedy first-fit. An item wider than `maxWidth` on its own still gets its own line rather than being dropped or re-tested forever: tag names are user data, so "wider than the screen" is a real input, and overflowing is visible where vanishing is not. `Line.width` excludes the trailing gap, so a row that exactly fits is not judged as overflowing |
